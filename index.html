Security

Designed for local development.

CppBook executes arbitrary local C++ code in child processes. It uses temporary execution directories, timeouts, process termination, limited environment propagation and cleanup.

Warning: Do not expose the current backend publicly. Shared or public deployments should add stronger sandboxing such as OS-level isolation and network restrictions.
FAQ

Common questions

Does CppBook require Python after installation?

The desktop shell is designed to start the packaged backend automatically. The current build still expects a C++ compiler such as g++ to be available on the target machine.

Is this a true persistent C++ interpreter?

No. CppBook uses compile-and-replay. It preserves normal notebook state by rebuilding and replaying earlier cells for the target cell.

Can I use it offline?

The core notebook experience is local. Any future AI functionality will be designed as an optional extension.

What is a .cppnb file?

It is CppBook's native notebook format (JSON-based) for storing code cells, Markdown content, and notebook structure.
